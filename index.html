RTA-V4 CASE STUDYTSMC 180nm · 2026

Dual-Mode Reconfigurable Spatial Accelerator

This project explores whether one physical fabric can support both structured matrix execution and flexible spatial kernels. The chip uses a 4×4 processing-element array that switches between CGRA-style INT8 execution and packed INT4 systolic execution, while reusing the same datapath and interconnect resources across both modes.

Project snapshot

  • ProcessTSMC 180nm
  • Fabric4×4 PE array
  • ModesCGRA INT8 / systolic INT4
  • I/O4 surrounding FIFOs
  • Host pathUART → FPGA → BSG-Link
  • Timing50 MHz closed
01 / WHAT IT DOES

Shared compute fabric for tensor and non-tensor kernels

The RTA-V4 fabric targets machine-learning workloads where dense matrix operations are important, but not the whole story. Between GEMM-heavy layers, models also need activations, elementwise arithmetic, comparisons, reductions, and data-format transformations. Instead of building separate engines, this design reuses one reconfigurable array for both structured systolic dataflow and more flexible CGRA-style kernels.

02 / MY CONTRIBUTION

External interface, verification, and physical design

  • Contributed external-interface RTL to move instructions and data between the host side and the compute fabric.
  • Built end-to-end verification around the real chip interfaces, including GEMM testing and returned-result checking against a golden model.
  • Led physical implementation through synthesis, place-and-route, extraction, DRC cleanup, and timing signoff.
03 / ARCHITECTURE

Two compute modes on one PE array

CGRA mode

In reconfigurable mode, the array executes streaming integer kernels such as ReLU, leaky ReLU, elementwise add/subtract, comparisons, shifts, and other lightweight operators.

Systolic mode

In systolic mode, the same array supports matrix-style dataflow for regular multiply-accumulate style computation, using packed INT4 operations with local accumulation.

Shared RMU

Each processing element includes a Reconfigurable Multiply Unit that shares one compact multiplier datapath across both modes, enabling signed INT8 behavior in CGRA mode and packed signed INT4 dot-product behavior in systolic mode.

04 / EXTERNAL INTERFACE

Instruction, data, and response flow

The chip communicates with the host PC through a UART-to-FPGA path, with the FPGA acting as a passthrough to the chip over BSG-Link. Incoming packets are depacketized into instructions and data. Data words are vectorized and routed to the north or west input FIFOs, depending on configuration. Outputs are drained from the east and south FIFOs, packetized, and sent back to the host together with acknowledgments from the instruction path.

Key datapath blocks

  • Depacketizer — parses incoming 32-bit packet words.
  • Instruction queue + decoder — issues control signals into the chip.
  • 1:2 vectorizer / data concat — packs two 32-bit words into 64-bit vectors.
  • Packetizer — frames output vectors and ACK responses back to the host.

Communication and control

  • BSG-Link presents a core-facing valid/yumi interface and a serialized DDR pad-side interface.
  • Four surrounding FIFOs support input from the north and west sides and output on the east and south sides.
  • ACK generation provides host-visible status snapshots after each decoded instruction.
05 / VERIFICATION

Tested at multiple stages

  • End-to-end RTL testing with chip-top testbenches that configured the fabric through BSG-Link and checked GEMM outputs against a software golden model.
  • Post-synthesis and post-place-and-route simulation using Hammer-based sim-syn and sim-par flows.
  • Additional bring-up testing for pad connectivity, reset sequencing, and scan-chain behavior.
  • FPGA prototyping with UART passthrough to exercise realistic host-chip communication.
06 / PHYSICAL DESIGN

Flat implementation with signoff-driven iteration

  • Manual floorplan placing the CGRA fabric near the center, with north / west input FIFOs and east / south output FIFOs around it.
  • External interface logic placed near the chip I/O side to reduce unnecessary routing distance.
  • Completed DRC, LVS, antenna, and timing checks, with final post-route timing meeting the 50 MHz target.
